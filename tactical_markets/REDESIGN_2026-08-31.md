## REBUILD — Premarket Briefing v1

MICRO's new job: **the 6:30 ET human window into the systems that do have edge.** The bot decides for itself but nothing tells Ian what state the machine is in before the day starts (today's kill-switch discovery is the proof). Read-only, files-on-disk, no cross-project imports — all contracts already exist.

Why this lives in MICRO and not the bot: an observer inside the observed system cannot report its own death — the failing component today *is* the bot's watchdog. MICRO is a separate process, repo, and schedule slot: an independent observer. That is also what justifies the external heartbeat (silent darkness in an observability layer is a real risk, not an inconvenience).

One Pushover, ~8 lines. **v1 core = sections 1–2** (pure file reads, no market-data dependency, ~1–2 days); **sections 3–4 ship best-effort in a 2b pass** — they need premarket quotes, the flakiest dependency (yfinance premarket is unreliable; VIX has none), so a failed quote drops the line, never the briefing:

1. **Regime** — from `market_dashboard/data/latest.json`: composite + band, regime, shock type. Staleness check (>36h → flagged STALE).
2. **Bot health** — from `tactical_markets_trading/data/last_successful_run.json` + `account_state.json`: last-success freshness, `entry_ok` + gate reason, open position count, equity vs peak (drawdown %). Today it would have read: *"⚠ bot: entries blocked (kill_switch 5 consecutive losses), last success 8/28, equity $102.7k (−0.0% off peak)."*
3. **Positions & flip proximity** — from `strategy_state_*.json` + live quotes: TQQQ distance to its trailing stop (off `position_peak_price`), SPY distance to 200d/50d MA (router flip levels). Lines within ~2% of triggering get a ⚠ prefix; calm lines stay terse.
4. **Overnight tape** — SPY/QQQ premarket vs prior close (flag |gap| ≥ 1%), VIX level + 5d change.

Mechanics: `run_tactical.py` stays the entrypoint (scheduler untouched); `src/briefing.py` replaces `sector_rotation.py` in the call path; every briefing logged to `data/briefings.jsonl` with `signal_type: "premarket_briefing"`. ~150–200 lines. Bot JSON reads are defensive: missing key → "unknown" in the line, never a crash, plus a one-line schema-drift warning when expected keys vanish (no formal versioning — one consumer).

**Scorer ships with v1:** every ⚠ line logs its trigger values; one command computes warning **precision** (⚠ followed within 3 days by the flagged event — stop hit, MA cross, gate change) and **recall** (events that occurred with no prior-day ⚠), from bot logs + prices.

**Then a two-week read**, same trick that worked in week 1:
- (a) "I acted on a ⚠ line" → tune thresholds, consider backlog items.
- (b) "All noise" → alert-only mode (push only when something is abnormal).
- (c) "Never read it" → delivery/format wrong, not content.

**Kill criteria, defaulted up front:** after the read, default = alert-only mode unless Ian affirmatively opts into the daily push; after 8 weeks with zero acted-on ⚠ lines, default = park the project. The predecessor died of decision-stall; this one ships with sunset defaults.
